# 單一壓縮檔的角色劇情任務拆分流程

本文件不是一般的角色圖片匯入規範，也不直接規定劇情或立繪的實作細節。它是**輸入只有一個壓縮檔**時的編排介面：先把不透明的 ZIP 拆成可驗收的小任務與明確產物，再依產物串接既有的圖片、劇本轉事件與場景流程。

適用例：使用者只提供 `drive-download-20260729T131245Z-1-001.zip`，並說明其中有角色個人劇情和角色圖基準。

## 總則

- 協調者只負責派發、驗收與交接；每個子任務只處理自己的輸入與輸出，不可越過驗收關卡直接修改 `project/`。
- 解壓、文字提取、圖片辨識可在 `tmp/character-story-import/<壓縮檔基名>/` 進行；劇情樓層、圖片註冊與既有素材的改動必須留到對應子任務被核准後。
- 壓縮檔內有多份劇本、圖片或未知檔案時，保留所有原始檔，各自建立產物；不得自行合併、刪除、猜測角色身分或挑選「看起來最像」的版本。
- 每個子任務完成時都要回傳產物路徑、判定結果與未解事項。未解事項交給 TODO，不可用假設補齊。

## 任務依賴圖

```text
ZIP
 └─ A. 解壓與盤點 ─┬─ B. 劇本文字提取 ─┐
                    └─ C. 角色圖辨識 ─ D. 六表情圖生成 ─ E. 遊戲圖片接入
                                           │
                                           └──────────────────────────────┬─ F. 劇本轉事件／場景
                                                                            └─ G. 整合驗收
```

`B` 與 `C` 可在 `A` 驗收後並行；`D` 只依賴 `C`；`E` 只依賴 `D`；`F` 需同時取得 `B` 的劇本文字，以及可用圖片的結論（`E` 完成，或已明確判定此劇本沒有可用角色圖）；`G` 最後執行。

## A. 解壓與內容盤點

**輸入：** 原始 ZIP。

**工作：** 以 Unicode／繁體中文檔名安全解壓至 `tmp/character-story-import/<壓縮檔基名>/`。PowerShell 使用 `-LiteralPath`；若解壓後檔名亂碼，停止並改用能保留 ZIP Unicode 檔名的工具，不能依亂碼判斷角色。

**輸出契約：**

- 原始檔未變更的解壓目錄。
- `intake-manifest.md`：列出每個檔案的相對路徑、副檔名、用途初判（劇本／圖片／未知）與是否可讀。
- `intake-questions.md`：檔名亂碼、未知格式、重複檔案或缺少角色名等阻塞事項；沒有問題時仍建立空清單。

**驗收／下一步：** 檔名可讀且盤點完整後，將 Word 類檔案交給 `B`，候選角色圖片交給 `C`。若 ZIP 根本無法解壓，流程停在本步。

## B. 劇本文字提取

**輸入：** `A` 的每份 Word 類劇本；不得輸入圖片或自行挑選的段落。

**工作：** 每份 `.docx` 只提取內容文字，產生同名 UTF-8（無 BOM）`.txt`。依 `word/document.xml` 的段落順序保留段落、換行和定位字元；不保留字型、排版、頁首頁尾、圖片、註解或修訂。`.doc`、PDF 或無法辨識的文件不得硬讀，改列為待轉檔。

**輸出契約：**

- `text/<原檔基名>.txt`，一份原始劇本對應一份文字檔。
- `script-manifest.md`：原檔與文字檔配對、文字提取狀態、章節／版本是否可判定。
- `script-questions.md`：無法轉檔、疑似重複版或章節順序不明等事項。

**正式故事來源落地：** 只要本步將檔案分類為角色劇情，必須在交給 `F` 之前，將 UTF-8 純文字版本放入 `project/story/`。TXT 來源直接保留原檔名；DOCX、PDF 或其他來源先依本步產生無 BOM TXT，再放入 `project/story/`。`tmp/character-story-import/` 的 `text/` 僅是提取中間產物，不得作為樓層轉換後的唯一故事來源。若 `project/story/` 已有同名檔案，不得覆蓋，改用帶來源或版本的可追溯檔名，並在 `script-manifest.md` 或 TODO 記錄原檔與正式檔配對。

**驗收／下一步：** 用明確 UTF-8 抽讀，確認中文、角色名、標點和段落順序正常。文字檔一律先交給 `F`；若有多份，不可在此步合併。

## C. 角色圖辨識與角色身分確認

**輸入：** `A` 的候選圖片、`B` 的文字檔及現有 `project/images/` 清單。

**工作：** 判定每張圖片是角色圖基準、其他素材或無法判定；核對角色名稱、髮型、服裝、配色、飾品及臉部特徵。已有專案角色圖時，明確記錄可沿用的檔名；不得用其他角色或相近名字代替。

**輸出契約：**

- `character-resolution.md`：支線持有者、角色 ID（若已確認）、基準圖路徑或既有角色圖路徑，以及判定依據。
- `character-questions.md`：身分未確認、圖片與劇本矛盾、或沒有任何可確認角色圖時的問題。

**驗收／下一步：** 角色與基準圖確認後才派發 `D`。若無可確認角色圖，不能生成表情圖或接入缺圖劇情；將阻塞事項交給 TODO，並讓 `F` 僅停留在劇本／待確認層級。

## D. 六表情表生成

**輸入：** `C` 已核准的單一角色基準圖與角色 ID。

**工作：** 這是獨立的圖片生成子任務，必須使用 `anime-expression-grid`、`imagegen` 與 `mota-avg-editor`。使用 `anime-expression-grid/assets/style.png` 作為畫風參考，但不得複製其中角色設計。產生一張 2 欄 × 3 列的半身綠幕表情表，格序固定為：喜／怒、哀／驚訝、慌亂／無表情。

**輸出契約：**

- `art/<角色ID>_expression_sheet.png`。
- `expression-validation.md`：六格順序、角色一致性、表情可讀性、黑色外框、純綠背景與無文字／水印的驗收結果。

**驗收／下一步：** 未通過任一格序、身分或邊緣驗收時，在本步重做；核准後才交給 `E`。不要直接以六格表當作遊戲中使用的立繪。

## E. 遊戲圖片接入

**輸入：** `D` 核准的六格表情表與 `C` 的角色 ID。

**工作：** 依既有 [圖片與立繪](images.md) 流程，先用 `remove_bk.py` 去背，再用 `split_emotion_image.py` 切成六張、檢查透明背景與格序、登錄 `project/data.js -> main.images`。這一步才有權寫入 `project/images/` 與圖片註冊檔。

**輸出契約：** 六張 `<角色ID>_{smile,angry,sad,surprised,panic,normal}.png`、其註冊證明與圖片驗收結果。

**驗收／下一步：** 六張圖、透明背景與註冊均正確後，將可用立繪清單交給 `F`。

## F. 劇本轉事件／場景

**輸入：** `B` 的單一已驗收 `.txt`、`C` 的角色結論，以及 `E` 的可用立繪清單（或明確的缺圖阻塞）。

**工作：** 依 [純文字轉事件 JSON](text-to-event-json.md)、[樓層與場景](floors.md) 與 [圖片與立繪](images.md) 建立場景。劇本來源不明、章節順序未確認、角色身分未確認或缺圖時，不得自行補劇情、猜選角色或改用其他角色立繪。

**輸出契約：** 場景／事件變更、每段劇本的來源文字檔路徑，以及 TODO 清單中所有未解問題。

## G. 整合驗收

**輸入：** `A` 至 `F` 的產物與 TODO。

**工作：** 逐一檢查產物鏈是否完整，確認每份 `.txt`、角色判定、表情表、切圖、圖片註冊與場景修改皆能追溯至 ZIP 中的原始檔。再依 [AI 撰寫檢查清單](checklist.md) 驗收。

**輸出契約：** 最終交付清單：原始 ZIP、解壓清單、`project/story/` 正式故事 TXT、文字提取產物、角色判定、六格表、六張立繪、場景變更與未解 TODO 的路徑／狀態。

**版本控制：** 每位角色完成 `G` 的整合驗收後，必須立刻為該角色的完整變更建立一次獨立 Git commit。不可把多位角色混在同一個 commit；若 ZIP 含多位角色，必須依角色重複 A 至 G，並在每位角色完成後各自 commit。提交前先確認 `git diff --cached --name-only` 與 `git diff --cached` 只包含該角色的 `project/story/` 正式故事 TXT、劇本、素材、共用註冊檔中屬於該角色的行，以及必要 TODO／流程變更；共用檔案不得整檔加入，未確認角色的素材另建待確認素材 commit。提交後立即用 `git show --stat --name-only <commit>` 複核，確認沒有跨角色或無關檔案。所有角色 commit 完成後，才可建立最後一個只更新 `AGENTS.md` 本節基準雜湊的 commit，將最後一個角色劇情 commit 的完整雜湊寫入；該基準 commit 不得混入任何劇情、圖片、註冊或 TODO 變更。
