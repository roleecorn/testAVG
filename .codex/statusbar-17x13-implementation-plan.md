# 左側狀態欄移除與 17x13 地圖改造流程

- 狀態：待執行
- 建立日期：2026-08-02
- 適用專案：`D:\coding\mota-js`
- 調查紀錄：`.codex/task-questions/20260802-230541-statusbar-17x13-feasibility.md`

## 1. 目標

將遊戲主要可視地圖從 `13x13` 改為 `17x13`，移除橫屏左側狀態欄，讓原本由左欄占用的寬度改由地圖使用，同時保留底部工具列及其存檔、讀檔、設定入口。

完成後的基準尺寸：

- 地圖邏輯尺寸：`17x13`
- 地圖像素尺寸：`544x416`（每格 `32x32`）
- 地圖畫面比例：`17:13`
- 底部工具列：保留，位於地圖畫布之外

## 2. 已確認決策

1. 不進行全域座標遷移。
2. 既有 `13x13` 樓層靠左保留，每列只在右側追加四格。
3. 不修改既有 `events`、`changeFloor`、`autoEvent`、Akiba 地點或其他座標鍵。
4. 移除左側狀態欄，也不允許狀態資訊改成覆蓋在 17 格地圖內。
5. 保留底部工具列，以及存檔、讀檔與設定入口。
6. 畫面縮小不是阻塞條件；完成基礎改造後可直接鎖定橫屏與固定比例。

## 3. 本次改造不包含

- 不重排 Akiba 店家、地點、人物或事件座標。
- 不把既有內容由左側搬到畫面中央。
- 不改寫劇情文本、分支、Flag 或事件內容。
- 不因畫面加寬而自動拉伸、裁切或重製所有背景圖。
- 不修改 `sample2` 等原本就大於可視區的樓層尺寸；它們繼續使用大地圖捲動。
- 未經額外要求，不執行 `git add`、commit 或 push。

## 4. 預期修改範圍

| 類型 | 主要檔案 | 預期處理 |

## 5. 執行流程

### A. 建立變更前基準

1. 先檢查 `git diff --cached`，確認使用者已暫存但仍待檢查的內容。
2. 再檢查 `git status --short`、`git diff --name-only`、`git diff --stat`。
3. 記錄原本就存在的未暫存或未追蹤變更，後續不得覆蓋或混入本次改造。
4. 列出 `project/data.js -> main.floorIds` 的所有有效樓層，並盤點各樓層的 `width`、`height`、`map`、`bgmap`、`fgmap` 實際尺寸。

### B. 改造遊戲畫布與狀態欄

1. 在 `libs/core.js` 將遊戲 `_WIDTH_` 設為 `17`，`_HEIGHT_` 保持 `13`。
2. 確認 `_PX_ = 544`、`_PY_ = 416`，其餘 UI 仍分別使用寬、高變數，不回退到正方形常數。
3. 在 `project/data.js` 開啟 `hideLeftStatusBar`。
4. 保持底部工具列可見，確認工具列仍包含存檔、讀檔與設定按鈕。
5. 修改 `project/functions.js -> drawStatusBar`：
   - 橫屏隱藏左欄時，不建立 `core.dymCanvas.status`。
   - 若舊流程曾建立該 canvas，需清除或刪除，避免殘留覆蓋。
   - 不在地圖左四格或右四格重新顯示半透明狀態面板。
6. 第一次啟動時確認總寬約等於舊版「13 格地圖＋左側狀態欄」，底部工具列則增加在地圖下方。

### C. 批次擴充樓層資料

對每個目前為 `13x13` 的樓層執行以下原子變更：

1. `width`：`13 -> 17`。
2. `height`：維持 `13`。
3. `map`：每一列尾端追加四個 `0`，列數維持 13。
4. 非空 `bgmap`：每一列尾端追加四個 `0`。
5. 非空 `fgmap`：每一列尾端追加四個 `0`。
6. 空陣列形式的 `bgmap: []`、`fgmap: []` 保持原狀。
7. 不修改任何既有座標內容，包括：
   - `events`
   - `changeFloor`
   - `beforeBattle`／`afterBattle`
   - `afterGetItem`／`afterOpenDoor`
   - `autoEvent`
   - `cannotMove`／`cannotMoveIn`
   - 英雄出生點與樓層切換落點
8. 原本寬度不是 13 的樓層不套用本批次變更，例如 `sample2` 保持 `26x26`。

### D. Akiba 專項處理

1. `Akiba.js` 的 `map`、`bgmap`、`fgmap` 只在右側補四格。
2. 保留 `(12,12)` 的 `idle_clock` 與所有既有視覺物件位置。
3. 不修改 `project/location-mappings.json`。
4. 不修改 Akiba 公共事件、Plugin 查詢邏輯或座標 Flag。
5. 擴充後重新驗證：
   - `events` 仍為 `0`
   - `mapNonZero` 不變
   - `fgNonZero` 仍為 `105`
   - 地點數仍為 `27`
   - mapped cells 仍為 `105`
   - 不存在地點重疊

### E. 視覺與 UI 像素座標檢查

地圖格座標不遷移，但 UI 圖片使用的是像素座標，需獨立檢查：

1. 背景圖仍以原始大小從 `(0,0)` 繪製，不做全域拉伸。
2. 基礎改造允許新增的右側 128 像素先顯示樓層 `defaultGround`；背景擴圖列為後續獨立素材工作。
3. 盤點以舊畫面中心 `x=208` 排版的 CG、選單與遮罩。
4. 僅在元素明顯需要保持置中時調整其 UI 像素 `x`；一般 320 像素寬 CG 若由 `x=48` 置中於舊畫面，可改為 `x=112` 置中於 544 像素畫面。
5. 既有角色立繪原則上保留原位置，不為了加寬而批量搬移。
6. 檢查固定 416x416 的自訂 UI（例如道具商店），確認它雖靠左顯示但操作區與點擊判定仍一致；是否重新置中另作最小範圍處理。

### F. 鎖定橫屏與畫面比例

在功能與樓層資料通過驗證後再執行：

1. 地圖 canvas 永遠保持 `544x416`，比例固定為 `17:13`。
2. 視窗縮放只使用單一 scale，同時套用寬與高，不允許非等比例拉伸。
3. 小視窗或直式螢幕仍使用橫屏版面，必要時整體縮小，不切回頂部狀態欄模式。
4. `hideLeftStatusBar` 在任何視窗寬高下都維持有效。
5. 底部工具列位於地圖之外；若計算整體容器高度，需額外加上工具列高度與邊框。
6. 驗證自動縮放與使用者既有 scale/localStorage 設定不會讓畫面變形或重新顯示左欄。

### G. 驗證與交付

#### 靜態資料檢查

1. 對所有修改過的 JavaScript 執行 `node --check`。
2. 驗證每個樓層：
   - `map.length === height`
   - 每列 `map[y].length === width`
   - 非空 `bgmap`、`fgmap` 的列數與列寬一致
3. 驗證所有由 13 格擴充的樓層，前 13 格內容與修改前完全相同，新增的第 14 至 17 格全部為 `0`。
4. 比較所有座標型物件的 key，確認改造前後完全一致。
5. 執行 Akiba 專項驗證及 `project/location-mappings.json` JSON 解析。

#### 遊戲內檢查

使用根目錄 `启动服务.exe` 啟動後檢查：

1. 左側狀態欄完全消失。
2. 地圖實際顯示 17 格寬、13 格高。
3. 地圖內沒有半透明狀態覆蓋層。
4. 底部工具列可見，存檔、讀檔、設定均可操作。
5. 逐類抽查普通 AVG 樓層、Akiba、`sample2` 大地圖。
6. Akiba 原有 13 格區域的移動、點擊地點與 idle clock 正常。
7. 新增右側四格可正常繪製與接受點擊，不影響原座標事件。
8. 對話框、選項、CG、立繪、淡入淡出與場景切換未被裁切。
9. 讀取舊存檔，確認舊 13 格地圖資料在缺少右側四格時能按空白格處理，不造成載入錯誤。
10. 在桌機寬螢幕、窄視窗與直式視窗各測一次固定比例行為。

#### 編輯器檢查

1. `editor.html` 能正常載入 17x13 樓層。
2. 13 格編輯視窗可水平捲動查看第 14 至 17 格。
3. 編輯並儲存後，樓層寬高與每列資料不會被截回 13。
4. `sample2` 等既有大地圖編輯不受影響。

#### Git 範圍檢查

1. 執行 `git diff --name-only`、`git diff --stat`、`git diff --check`。
2. 確認沒有修改劇情來源文本、角色素材、BGM 或其他無關檔案。
3. 將既存工作樹變更與本次改造分開回報。
4. 未經使用者要求，不變更 staged/index 狀態，也不建立 commit。

以下條件全部成立才可宣稱改造完成：

- 遊戲地圖可視區為 `17x13`。
- 左側狀態欄與地圖內狀態覆蓋都不存在。
- 底部工具列、存檔、讀檔、設定功能正常。
- 所有由 13 格擴充的樓層只在右側新增四格。
- 既有地圖座標、事件座標與 Akiba mapping 均未遷移。
- 樓層資料尺寸檢查、JavaScript 語法檢查與 Akiba 專項檢查通過。
- 舊存檔、普通 AVG 場景、Akiba、大地圖與編輯器均完成實際測試。
- 固定比例時只整體縮放，不發生非等比例變形，也不切回狀態欄版面。

## 7. 建議交付切分

若後續要正式實作，建議分成兩個可獨立驗證的變更批次：

1. **功能批次**：畫布 17x13、左欄移除、狀態覆蓋移除、樓層右側補四格、底部工具列保留、固定比例。
2. **視覺批次**：背景擴圖、需要置中的 CG／自訂 UI 像素位置調整。

功能批次先通過完整驗收，再開始視覺批次，可降低一次修改過多檔案時的回歸風險。
